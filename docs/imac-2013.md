# iMac 21,5" fin 2013 — machine de travail permanente

Objectif : faire de cet iMac la machine allumée en permanence sur laquelle stocker et exécuter
les projets perso, en attendant le Mac mini. Elle doit donc pouvoir faire tourner Claude Code
en local, encaisser des builds, et rester accessible à distance.

## 1. Fiche machine

Relevé le 12 septembre 2026 par `scripts/imac-preflight.sh`.

| | |
|---|---|
| Modèle | iMac14,1 — 21,5" fin 2013 |
| Processeur | Intel Core i5-4570R — Haswell, 4 cœurs / 4 threads, 2,7 GHz (turbo 3,2) |
| Cache | 256 Ko L2 par cœur, 4 Mo L3 |
| Graphismes | Intel Iris Pro 5200 (intégrée, compatible Metal) |
| Mémoire | 16 Go — 2 barrettes SO-DIMM DDR3L 1600, **maximum officiel du modèle**, rien à gagner de ce côté |
| Disque | **Samsung SSD 860 EVO 250 Go** en interne — 100 Go libres |
| Système | macOS Catalina 10.15.8 (build 19H2036), APFS, volume système en lecture seule |
| FileVault | désactivé |
| SIP | activé |
| Réseau | Wi-Fi seulement (en1, BCM4360 802.11ac), pas d'Ethernet branché |
| Énergie | veille à 3 min, disques à 10 min, **pas de redémarrage automatique après coupure** |
| Firmware | Boot ROM 433.140.2.0.0, SMC 2.14f24 |
| Outils | Command Line Tools en cours d'installation (git et python3 n'étaient que des stubs) |

Le numéro de série et l'UUID matériel ne sont volontairement pas écrits ici : ils servent à
l'assistance Apple et à l'identification de la machine, ils n'ont rien à faire dans un dépôt
public.

**Le point qui change tout : le disque est déjà un SSD.** C'était la grande inconnue, et la
réponse est la bonne. Un Samsung 860 EVO en SATA III sur un Haswell 4 cœurs avec 16 Go, ça fait
une machine de travail tout à fait correcte. Il n'y a aucun achat de disque à prévoir, et la
seule vraie limite restante est la version de macOS.

**La machine a déjà été ouverte** : SSD posé à la place du disque d'origine et mémoire portée à
16 Go, ce qui suppose d'avoir décollé la dalle et démonté la carte mère. Deux conséquences.
D'abord, le Hitachi 1 To d'origine sert aujourd'hui de disque externe — c'est **la cible
idéale pour Time Machine**, et cela change la nature du risque de toute l'opération. Ensuite,
si les 250 Go deviennent étroits à deux systèmes, remplacer le SSD par un 1 To est une
manipulation déjà pratiquée ici, pas un saut dans l'inconnu.

## 2. Pourquoi Claude Code refuse de s'installer

Rien à voir avec le matériel, tout avec la version de macOS :

- Claude Code demande **macOS 13.0 ou plus récent**. L'application Claude Desktop demande
  **macOS 11 minimum**, donc elle non plus ne s'installera pas ici.
- L'iMac14,1 s'arrête officiellement à **macOS Catalina 10.15.x**. macOS Big Sur exige déjà un
  iMac de 2014 ou plus récent : ce modèle rate la marche d'une génération.

Il y a donc exactement deux sorties : rendre la machine capable de faire tourner un macOS
récent (plan A), ou exécuter l'agent ailleurs que dans macOS (plan B). Les deux peuvent
cohabiter, et le plan B est disponible tout de suite.

## 3. Plan A — macOS Sequoia via OpenCore Legacy Patcher

OpenCore Legacy Patcher (OCLP) fait démarrer un macOS récent sur un Mac que Apple ne supporte
plus, et réinjecte les pilotes retirés. C'est la voie normale pour ce modèle.

### Viser Sequoia 15, pas Tahoe 26

- La dernière version d'OCLP (2.5.0, 8 septembre) supporte **macOS Sequoia** ; le support de
  **macOS Tahoe 26 n'est pas publié**, le suivi se fait dans l'issue #1167 du dépôt et aucune
  date n'est annoncée — l'équipe écrit elle-même qu'une sortie « dans les circonstances
  actuelles est incertaine ».
- Apple a de plus retiré 8 Mac Intel supplémentaires de Tahoe, ce qui allonge la liste des
  correctifs à écrire.

Donc : **cible = Sequoia 15.x**, qui satisfait déjà le prérequis macOS 13+. On repassera à
Tahoe quand OCLP le publiera, sans rien refaire d'autre que la mise à jour.

### Où l'installer : un second volume APFS sur le SSD interne

Le disque interne étant déjà un SSD, il n'y a aucune raison d'acheter un disque externe pour la
vitesse. La bonne méthode est d'**ajouter un volume APFS** dans le conteneur existant et d'y
installer Sequoia, en laissant le volume Catalina intact.

- Les volumes APFS d'un même conteneur **partagent l'espace libre** : pas de partition à
  dimensionner, Sequoia prend ce dont il a besoin sur les 102 Go disponibles.
- Le retour arrière reste immédiat : on démarre en maintenant <kbd>alt</kbd> et on choisit le
  volume Catalina, qui n'a pas bougé.
- Prévoir de garder **40 Go libres au minimum** après installation. Sur un SSD de 250 Go partagé
  entre deux systèmes, c'est le point à surveiller dans la durée.

À prévoir, côté matériel : une **clé USB de 16 Go ou plus** pour l'installeur, et un **disque
externe pour Time Machine** — cette machine a 13 ans et va tourner en permanence.

### Déroulé

0. **Sauvegarde Time Machine complète** sur un disque externe. Non négociable.
1. Disque interne → Utilitaire de disque → sélectionner le conteneur `disk1` → **+** → nouveau
   volume APFS nommé `Sequoia`.
2. Télécharger OCLP 2.5.0 depuis les *releases* du dépôt `dortania/OpenCore-Legacy-Patcher`.
3. Dans OCLP : *Create macOS Installer* → Sequoia, sur la clé USB.
4. *Build and Install OpenCore* → installer l'EFI sur le disque interne (`disk0s1`).
5. Redémarrer en maintenant <kbd>alt</kbd>, choisir *EFI Boot*, installer Sequoia sur le volume
   `Sequoia`.
6. Au premier démarrage, OCLP propose les **Root Patches** : les accepter. C'est ce qui rend
   l'accélération graphique au Iris Pro 5200 ; pour Haswell sous Sequoia, cela passe par
   `MetallibSupportPkg`. Sans cette étape, l'interface rame et la machine chauffe pour rien.
7. Définir le disque de démarrage par défaut sur `Sequoia` une fois tout validé.

FileVault est déjà désactivé et c'est très bien : c'est une source connue d'ennuis avec OCLP,
et un volume chiffré empêche de toute façon un redémarrage automatique sans intervention
humaine.

### Entretien, et le piège à connaître

- **Chaque mise à jour de macOS efface les root patches.** OCLP les repropose au redémarrage :
  tant qu'ils ne sont pas réappliqués, il n'y a pas d'accélération graphique.
- Donc : **désactiver les mises à jour automatiques** et les faire à la main, en gardant une
  demi-heure devant soi pour rejouer les patches. Sur une machine censée tourner seule, une
  mise à jour automatique de nuit est le scénario qui la laisse dans un état dégradé pendant
  trois jours sans que personne s'en aperçoive.
- Ne pas mettre à jour un macOS patché juste avant de partir en vacances.

## 4. Plan B — Claude Code dans une VM Linux, sans toucher à macOS

Utilisable **aujourd'hui**, sur le Catalina actuel, et bon filet de sécurité même après le
passage à Sequoia : Claude Code s'installe nativement sur Linux (Ubuntu 20.04+, Debian 10+).

1. VirtualBox 6.1 (dernière lignée qui accepte Catalina comme hôte).
2. Ubuntu 22.04 LTS en invité : 2 vCPU, 6 Go de RAM, 40 Go de disque — sur un SSD de 250 Go
   déjà occupé à moitié, ne pas viser plus grand.
3. Dans la VM : `curl -fsSL https://claude.ai/install.sh | bash`, puis `claude`.
4. Accès depuis macOS par SSH sur la VM, projets stockés dans la VM (pas dans un dossier
   partagé : les dossiers partagés VirtualBox sont lents et cassent les `git status`).

Moins élégant qu'un macOS récent, mais opérationnel en une soirée et sans aucun risque pour la
machine.

## 5. Régler la machine pour tourner en permanence

Les réglages actuels sont ceux d'un poste de bureau : **veille au bout de 3 minutes, aucun
redémarrage après coupure de courant**. Inutilisable pour une machine qu'on veut joindre à
distance. À corriger :

```bash
# jamais de veille, redémarrage automatique après coupure de courant
sudo pmset -a sleep 0 disksleep 0 displaysleep 15 womp 1 autorestart 1 powernap 0
```

`scripts/imac-24-7.sh` applique exactement ça, en affichant d'abord ce qu'il ferait. Il demande
`sudo`, donc un compte administrateur.

Le reste, dans l'ordre d'importance :

- **Ethernet.** La machine est en Wi-Fi seul. Pour un poste allumé en permanence et joint par
  SSH, un câble vers la box supprime d'un coup les déconnexions et les réveils ratés.
- **SSH** : Préférences Système → Partage → Session à distance. Puis clé publique uniquement,
  mot de passe refusé (`PasswordAuthentication no` dans `/etc/ssh/sshd_config`).
- **Accès depuis l'extérieur** : Tailscale plutôt qu'une redirection de port sur la box. Pas de
  port SSH exposé sur Internet, pas d'IP fixe à gérer.
- **tmux** : indispensable pour qu'une session lancée à distance survive à la coupure de la
  connexion.
- **Ouverture de session automatique** au démarrage, sinon un redémarrage après coupure laisse
  la machine bloquée sur l'écran de connexion. FileVault étant désactivé, c'est possible.
- **Compte administrateur** : les trois échecs de `sudo` au premier essai laissent penser que
  le compte `tonton` n'en est peut-être pas un. À vérifier, c'est nécessaire pour la suite.
- **Time Machine** vers un disque externe. 13 ans, et bientôt allumé en permanence.

## 6. Ce qu'on peut raisonnablement lui demander

- Builds et tests Python, Node, Go, compilations C : oui, un Haswell 4 cœurs sur SSD reste
  confortable.
- Serveurs de développement, bases de données locales, conteneurs : oui, 16 Go suffisent.
- Modèles de langage en local : non. Pas de GPU exploitable, 16 Go non extensibles.
- Compilations très lourdes ou tâches longues et parallèles : c'est le rôle du futur Mac mini ;
  ici il faut accepter des temps 3 à 5 fois plus longs qu'une machine Apple Silicon récente.
- Stockage : 250 Go partagés entre deux systèmes. Les gros volumes de données iront sur un
  disque externe, pas sur l'interne.

## 7. Pièges déjà rencontrés

**`apt` n'existe pas sur macOS.** Les instructions d'installation en `apt` / `.deb` publiées
par Anthropic sont celles de **Claude Desktop pour Linux**, elles ne s'appliquent pas ici. Ce
qui trompe : macOS *possède* un `/usr/bin/apt`, mais c'est l'outil d'annotations de Java, sans
rapport. D'où le message `No Java runtime present, requesting install` quand on tente la
commande — il faut refuser l'installation de Java proposée, elle ne sert à rien. Ces commandes
n'installent rien et ne cassent rien : `/etc/apt/` et `/usr/share/keyrings/` n'existent pas
(`tee: No such file or directory`, `curl: (23) Failed writing body`), et `/usr/share` est de
toute façon protégé par SIP.

**Le `.dmg` de Claude Desktop pour macOS ne sert à rien ici non plus** : l'application demande
macOS 11 minimum. Les images disque montées (`/dev/disk2`, `/dev/disk3`, volumes « Claude »)
peuvent être éjectées.

**Ne pas coller un script multi-lignes dans zsh.** Le shell par défaut de macOS interprète le
`!` comme un rappel d'historique et répond `zsh: event not found`. Il faut télécharger le
fichier et l'exécuter, pas le coller.

**zsh n'accepte pas les commentaires en fin de commande.** Coller
`bash script.sh --apply  # commentaire` donne `zsh: number expected` : les parenthèses du
commentaire sont lues comme un qualificateur de glob. Soit on colle la commande seule, soit on
ajoute une fois pour toutes `setopt interactive_comments` à `~/.zshrc`.

**`git` et `python3` peuvent répondre « présent » sans être installés.** macOS fournit des
stubs qui déclenchent l'installation des Command Line Tools au premier appel — c'est ce qui
s'est produit ici.
